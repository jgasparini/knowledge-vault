# PARA guide — decision rules and examples

A practical reference for where to file notes. The goal is to be decisive — an imperfect filing decision is better than a note left in the inbox.

---

## The four folders

### 01 — Projects

Active work with:
- A clear goal (you can write "done looks like X")
- A deadline or expected completion
- An owner (you, or someone you are accountable to)

A project has a finish line. When you reach it, the project moves to archive.

**Examples:**
- Deliver data platform architecture review by end of Q2
- Prepare for annual performance review — June
- Read and summarise "Thinking in Systems" by end of month

**Not projects:**
- "Improve the data platform" (no deadline, no finish line → Areas)
- "Notes on dbt" (no goal → Resources)

---

### 02 — Areas

Ongoing responsibilities with no end date. You maintain these indefinitely.

An area has a standard you are trying to meet, not a goal you are trying to reach.

**Examples:**
- Leadership and team management
- Architecture guild (you are a standing member)
- Personal health
- People — contacts and relationships

**Distinction from Projects:**
If you can finish it, it is a Project. If you just maintain it, it is an Area.

---

### 03 — Resources

Reference material you may want to retrieve later. No ongoing responsibility — just useful information.

File here when you want the note to be findable but you are not responsible for maintaining the topic.

**Examples:**
- Notes on the medallion architecture pattern
- Article on dbt vs Spark trade-offs
- Book highlights from "Staff Engineer"
- Meeting notes that are informational but not tied to an active project

**Distinction from Areas:**
You are not responsible for maintaining the topic. You just want to be able to find the note.

---

### 04 — Archive

Completed, inactive, or low-signal material. Keep it — do not delete it — but stop actively maintaining it.

Move to archive when:
- A project is complete or cancelled
- An area of responsibility ends
- A resource has not been accessed in 90+ days and is unlikely to be needed

**The archive is not a bin.** It is a searchable store of past work. Claude can surface it when relevant.

---

## Common edge cases

| Note type | Where it goes | Why |
|-----------|--------------|-----|
| Meeting note with no active project | Resources | Informational — file under the topic, not the meeting |
| Meeting note for an active project | Inside the project subfolder | Tied to a deliverable |
| Article you saved but have not read | Resources | Aspiration is not a project |
| A person you work with on a project | Areas/people | People are maintained, not completed |
| A decision made in a meeting | Inside the relevant project note (decisions log) | Not a standalone note |
| An idea with no clear home | Resources | File under the topic — let Claude suggest tags |
| An old project that ran out of steam | Archive | Stop maintaining it — retrieve it if it restarts |

---

## The 30-second filing test

Ask yourself:
1. Does this have a deadline and a finish line? → **Projects**
2. Is this something I am responsible for maintaining? → **Areas**
3. Might I want to find this again someday? → **Resources**
4. Is this done or inactive? → **Archive**

If in doubt, file in **Resources**. It is always better to retrieve from Resources than to create false urgency by putting something in Projects.
